# Gate-then-tilt integration between forecaster and optimizer

The forecaster and optimizer are loosely coupled through a two-step integration: first **gate**, then **tilt**. The optimizer computes base Weights using HRP or MVO without any forecast input. If Forecasts are available, the pipeline (1) zeros out the Weight of any ticker whose `direction_prob` falls below a configurable threshold (default 0.50), then (2) multiplies surviving Weights by rank-derived Tilt Factors (top-quartile tickers get 1.2×, bottom-quartile 0.8×) and re-normalises to sum to 1.0. We considered feeding predicted returns directly into MVO's expected-return vector (the textbook approach), but rank predictions don't carry magnitude information and converting them to synthetic return estimates introduces a fragile mapping. The gate-then-tilt design lets the optimizer work standalone (no forecasts needed for a pure risk-parity allocation), keeps the forecaster's output a simple two-field struct, and avoids coupling the optimizer's internals to the model's prediction scale.
