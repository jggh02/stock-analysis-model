# Structural enforcement of look-ahead bias prevention

The forecasting and backtesting pipeline enforces seven look-ahead bias rules structurally — the code makes violations impossible rather than relying on developer discipline. The rules are: (1) temporal-only splits, (2) point-in-time features via the Feature Registry, (3) t+1-to-t+horizon label alignment, (4) a configurable Embargo Period between train and test windows, (5) split/bonus-adjusted prices only, (6) benchmark return alignment to the same walk-forward dates, and (7) Feature Registry lookback validation with NaN-masking. We considered a lighter approach (convention + code review) but rejected it: look-ahead bias is the single most common source of unreproducible backtest results in hobby quant projects, and once it leaks in, every downstream metric is silently wrong. The structural overhead (decorators, registry checks, enforced date fencing) is modest and pays for itself the first time it catches a bug.
